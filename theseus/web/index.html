Theseus reviews every Terraform change as a graph in FalkorDB. The graph

One FalkorDB graph per commit, and a GRAPH.COPY for every candidate fix. Cypher finds the paths; the engine computes the minimum cut and simulates each fix. Node labels follow Cartography's ontology, so a live cloud map can feed the same engine.

Get started

Connecting a repository takes five steps; the dashboard's Setup page ticks each one off as Theseus sees it done.

  1. Run the backend next to FalkorDB: one FastAPI service, settings in .env.
  2. Install the GitHub App on the repository. It comments, checks, and commits a fix only after a person asks.
  3. Add theseus.yaml and the workflows: what must keep working, and the plan jobs CI already runs. Require the Theseus check on main.
  4. Build main's graph once from Actions; after that it rebuilds on every push and nightly.
  5. Open a pull request. Within seconds the check reads "Reviewing"; minutes later the comment and the fix arrive.

For developers: /plugin install theseus --marketplace AjinkyaTaranekar/theseus in Claude Code, or python -m theseus check in any terminal.

The demo company is synthetic. Answers shown here are the engine's own, computed on this server from the fixtures when it started; never a copy of a stored answer key. Theseus models a defined AWS IAM subset and Python code; what it can't model comes back UNKNOWN, and a path is a modeled route, not proof of an attack.
