## F4 design and handoff

- The world has 60 Terraform resources: 59 resources of types in the merged modeled set plus the deliberately skipped ECS cluster. It contains 4 users, 3 groups, 11 roles, 6 workload definitions and the inputs for 10 data nodes; E1 verifies graph counts.
- Each field needed for identity, policy, trust, environment, membership and task lookup is literal and known at plan. Computed bucket/secret policy attributes are ignored exactly as P1 specifies; no unknown marker is erased from the plans.
- plan.sh creates a clean temporary Terraform root containing configuration only, disables the backend and refresh, isolates ambient AWS profiles/session tokens and shared configuration, and uses the provider's mock credentials/skip settings. Existing state cannot be read. JSON replaces its destination only after a successful show; temporary paths are cleaned even if output-file creation fails.
- make_fixture.py stages each scenario, rejects malformed/incomplete plans, and finishes all its plans before publishing any inputs. It backs up only its explicit owned paths and rolls back publication errors; if rollback fails, recovery files remain on disk with their location reported. Human files remain untouched. It excludes state/providers/caches, writes LF text with sorted JSON keys, and removes only the top-level Terraform timestamp.
- Intern/public head changes are appended, so baseline resource and Sid lines do not move. Finding/scan use base only. code-pr explicitly reports the C1 dependency instead of generating a misleading fixture.
- The user approved world: demo-infra and advisory fields id/action/affected_versions/text in this chat. Consumers should resolve fixture-local base/head from mode; world labels the source world, not a path to use instead of the copied side.
- Source lines are ready for local review. F5 may use them after the humans accept the diff; further edits require regeneration and renewed evidence review.
- No engine, contracts, keys, board items, other PR branches, or expected.json files were changed. This review file is the only scope addition beyond F4's brief and AI_USE.md; it records the board/dependency audit requested in this chat.
