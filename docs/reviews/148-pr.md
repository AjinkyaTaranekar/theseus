## Why

The imported demo world has **22 Resource nodes**, while existing sensitivity recordings cover **13**. The historical ten-resource test is not a whole-world evaluation. The production fallback returns class labels without probability vectors, repeated requests overwrite hash-named recordings in a shared directory, and the wrapper's successful-attempt timing excludes earlier retries/backoff.

The proposed protocol scores raw predictions before overrides, preserves separate recordings for every sample and reports full-batch latency. No other open feature must merge first: S2's pending PR #117 (task #39), review-latency work #142 and scanner work #143 need coordination, not a shared implementation dependency.

## Decisions for review

1. Humans review and save a complete label key for the pinned corpus; no agent writes the answer key.
2. Report the existing fallback's Brier as **N/A — label-only, uncalibrated**, with vector coverage. A numeric fallback score requires a separately approved probability-output prompt change.
3. Use `python -m bench.jev`, one warmup plus twenty measured batches per provider, a fixed primary sample, strict four-class Brier validation and isolated per-sample recording directories.
4. Generate one dated README block from retained artifacts, preserving S2's independent results and the separately scoped historical steering measurement.

The design changes no production code, frozen contracts, dependencies, prompts, fixtures, golden comparisons, answer keys, recordings or published results. It does not claim model calibration, completed human review or passed demo gates.
