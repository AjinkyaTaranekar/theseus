## E1 boundaries and composition

- Terraform owns managed plan resources, recursive modules, unknown fields and exact source locations. It does not import the cloud adapter. A reference is resolved only from a known name; ambiguous or composite unresolved inputs remain unknown. Computed bucket/secret policy attributes are ignored as specified. No plan input is mutated.
- AWS owns principal ARNs, data/workload catalog interpretation, memberships, workload role bindings, secret/database links and environment bindings. Every catalog entry is exercised; role joins support direct fields and indirect resources, with ECS family/revision/ARN forms. Execution roles never supply workload identity. The merged E2 evaluator supplies access edges; it is not reimplemented here.
- AwsAdapter receives a copy of the world config at construction. E3's composition root must construct it from the same config as load_world. The protocol stays unchanged, and core names no vendor. Patched-world simulation must preserve or reconstruct that config in E5.
- Core loads config and files, records all managed resources and skipped type counts, passes CI identities to the cloud adapter, and gives the composed structural rows to the code adapter. Rows, edges, grants, evidence and unknowns are sorted; duplicate edges merge grants and evidence, and unknown dominates. Conflicting node facts or edge properties raise IngestError rather than silently choosing a claim.
- Requirement citations come from YAML source marks only when the source still equals the loaded config. Otherwise evidence is explicitly unknown with a reason. The same rule applies to source addresses/Sids that cannot be found uniquely, including remote modules.
- BuildRows' frozen labels argument contains class strings. It applies human overrides first and treats absent labels as unclassified. A2's richer JevAnswer/source handling stays in agent.sensitivity.apply: E3 must use that after building rows to retain fallback provenance, rather than reducing fallback answers to strings.
- GithubAdapter and PythonAdapter deliberately return empty reads until FM1 and C2. The imported world still carries their files. Their own workflows/code must not be treated as parsed facts here.
