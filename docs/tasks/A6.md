# A6: MCP server and tool trace

**Lane:** Agent and GitHub | **Stage:** Beat 2: Fix it | **Size:** M | **Needs first:** F2 | **Branch:** `a6-mcp`

## The feature

One tool registry with the ten tools in 05, served over MCP and used directly by the fix agent, with a recorder that logs every call's input, summary and time into the result's `tool_trace`.

## Why it matters

Track 01 asks for graph algorithms as agent tools and tool selection through MCP. The trace is the proof that the agent chose its tools: judges ask "is it an agent or a script?"

## Files

| File | Action | Purpose |
| --- | --- | --- |
| `theseus/mcp/tools.py` | create | `Tool(name, description, input_schema, handler)` for each tool; `ToolContext` holds the store, rows and graph names of the current analysis |
| `theseus/agent/trace.py` | create | A context-managed recorder that wraps every handler in the registry and yields `ToolCall` records |
| `theseus/mcp/server.py` | create | MCP Python SDK server over the registry (stdio), started with `python -m theseus.mcp.server <fixture>` |
| `.mcp.json` | create | So Claude Code can connect to the server on a fixture |
| `tests/unit/test_mcp_tools.py` | create | Every tool on the fixtures with `MemoryStore`; inputs validate against their schemas |
| `tests/unit/test_trace.py` | create | Calling three tools records three `ToolCall`s in order, with input, summary and milliseconds |

## Steps

1. Write the schemas from the 05 table.
2. Handlers call engine functions; no logic in the tools.
3. Wrap the registry with the recorder.
4. Connect Claude Code through `.mcp.json` and call every tool once.
