# F3: Run it: Compose, API stub and VM deploy

**Lane:** Foundation | **Stage:** Foundation | **Size:** M | **Needs first:** F2 | **Branch:** `f3-run-it`

## The feature

FalkorDB in Docker, a graph client, a FastAPI app whose `POST /analyze` returns a stub result built from an `expected.json`, and the same stack live on the Oracle VM behind Caddy with HTTPS, deployed by one script.

## Why it matters

The Agent lane builds the comment, the Action and the Try-it page against this stub while the engine is being written, and the Action needs a public URL. Both halves edit `deploy/docker-compose.yml`, so one session does them.

## Steps

1. Pin the FalkorDB image tag that P1 confirmed.
2. Write the smoke test first and run it against the container.
3. Check the VM shape (`uname -m`, `nproc`, `free -h`), point the domain at it, open only 80 and 443.
4. Deploy and curl `/health`. Record in the PR which `algo.*` procedures the image lists.

## Done when

- [ ] `docker compose -f deploy/docker-compose.yml --profile dev up -d` starts FalkorDB
- [ ] The smoke test passes
- [ ] `https://<DOMAIN>/health` returns ok, and FalkorDB has no public port
- [ ] `/analyze` returns a valid stub
- [ ] `pytest -q` and `ruff check .` pass, and `AI_USE.md` has this task's line
