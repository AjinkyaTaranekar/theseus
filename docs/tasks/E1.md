# E1: Importer: plan, structure, workloads and coverage

**Lane:** Engine | **Stage:** Beat 1: See it | **Size:** L | **Needs first:** F2, F4 | **Branch:** `e1-importer`

## The feature

Turn a world root (plan JSON, `.tf` files, `theseus.yaml`) into graph rows: every node, the structural edges for Lambda and ECS workloads, evidence with file and line on every edge, and the coverage count of every skipped resource type.

## Why it matters

Beat 1's claim, "every step cites its file and line", starts here, and so does the honest "we read about 110 resources and modeled about 60".

## Files

| File | Action | Purpose |
| --- | --- | --- |
| `theseus/importer/world.py` | create | `load_world(root)` for `demo-infra/` or a fixture side; `World` holds resources, skipped types, unknowns, tf texts, workflow texts, code texts, config |
| `theseus/importer/plan.py` | create | Resources from `planned_values` (root and child modules); unknown-until-apply fields, only those the importer reads, with their references; resolve names through references |
| `theseus/importer/source_index.py` | create | Find a resource header line, or a `Sid` line inside it, in files relative to the world root |
| `theseus/importer/build.py` | create | `build_rows(world, labels, access=None, workflows=None, code=None)`: nodes for every kind (users, groups, roles, Lambda and ECS workloads, s3 locations, secrets, databases, DynamoDB tables, requirements), `MEMBER_OF`, `RUNS_AS` (Lambda `role`; ECS service to its task definition's `task_role_arn`), `UNLOCKS`, `FOR`, `NEEDS`, `HAS_ENV` from Lambda and ECS environments, env tags, unknown policies, `Coverage`. The `access`, `workflows` and `code` hooks are filled by E2, FM1 and C2 |
| `tests/unit/importer/` | create | Unknown-field detection on a tiny plan dict (an unknown subnet ID is ignored, an unknown policy is not); source index lines on `demo-infra/` files; ECS `RUNS_AS` resolves `family:revision`; coverage counts a made-up skipped type; build counts on `fixtures/intern` base and head |

## Steps

1. Write tests from the intern fixture first: node counts per kind (4 users, 3 groups, 11 roles, 6 workloads, 10 resources, 17 requirements), the new `MEMBER_OF` edge in head, its evidence file and line.
2. Implement `plan.py`, then `source_index.py`, then `build.py`.
3. Run against every fixture; nothing may raise.

## Done when

- [ ] Intern base has 4 users, 3 groups, 11 roles, 6 workloads, 10 resources and 17 requirements; head adds exactly one `MEMBER_OF` edge
- [ ] Every edge has evidence with a file and line, or `unknown` with a reason
- [ ] Both ECS workloads run as their task roles, never as `ecs-task-execution`
- [ ] An unknown policy becomes an unknown edge and an entry in `unknowns`; every skipped type is counted
- [ ] `pytest -q` and `ruff check .` pass, and `AI_USE.md` has this task's line

## Out of scope

- IAM evaluation and `CAN` or `CAN_ASSUME` edges (E2)
- Workflows (FM1)
- Code (C2)
- FalkorDB (E3)
