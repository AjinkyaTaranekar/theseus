# E1: Importer: plan, structure, workloads and coverage

**Lane:** Engine | **Stage:** Beat 1: See it | **Size:** L | **Needs first:** F2, F4 | **Branch:** `e1-importer`

## The feature

Turn a world root (plan JSON, `.tf` files, `theseus.yaml`) into graph rows: every node, the structural edges for Lambda and ECS workloads, evidence with file and line on every edge, and the coverage count of every skipped resource type.

## Why it matters

Beat 1's claim, "every step cites its file and line", starts here, and so does the honest "we read 122 resources and modeled 70".

## Files

| File | Action | Purpose |
| --- | --- | --- |
| `theseus/importer/world.py` | create | `load_world(root, plan, adapters) -> World` for `demo-infra/` or a fixture side: the IaC adapter reads resources and unknown fields; types the cloud adapter does not model are counted in `skipped_types`; `iac_files`, `ci_files`, `code_files` and `config` come from the world root. Names no vendor |
| `theseus/adapters/terraform/plan.py` | create | Resources from `planned_values` (root and child modules); unknown-until-apply fields, only those the importer reads, with their references; resolve names through references |
| `theseus/adapters/terraform/source_index.py` | create | Find a resource header line, or a `Sid` line inside it, in files relative to the world root |
| `theseus/importer/build.py` | create | `build_rows(world, labels, adapters) -> GraphRows`: the CI adapter's rows and identities, the cloud adapter's rows (given those identities), the code adapter's edges, then requirement nodes with `FOR` and `NEEDS`, sensitivity labels, env tags and `Coverage`. Names no vendor; an adapter with no files contributes nothing |
| `theseus/adapters/terraform/adapter.py` | create | `TerraformAdapter` (`IacAdapter`): `read` through `plan.py`, `locate` through `source_index.py`; `render` raises `PatchError` until E9 |
| `theseus/adapters/aws/resources.py` | create | Users, groups and roles; a Resource node for every `data` entry in `catalog.yaml` (S3 per data location), with `category`, `provider`, its category label and `arn_pattern` from the entry's `arn`; a Workload node for every `workloads` entry, with its label and `RUNS_AS` to the role its `role` names (directly, or through `via`); `MEMBER_OF`; `UNLOCKS`; `HAS_ENV` from Lambda and ECS environments; unknown policies. No per-service code: a new service is a catalog entry |
| `theseus/adapters/aws/adapter.py` | create | `AwsAdapter` (`CloudAdapter`): `rows` from `resources.py` plus E2's `access.derive_access_edges` (FM1 adds trust edges); every principal node carries `arn` and every resource node `arn_pattern`, which E2 reads; `ops_for` and `apply_ops` raise until E6 and E5; `ops_schema` from `ops.py` |
| `theseus/adapters/github/adapter.py`, `theseus/adapters/python/adapter.py` | create | Adapters that read nothing yet, so `build_rows` runs before FM1 and C2 |
| `tests/unit/importer/`, `tests/unit/adapters/terraform/`, `tests/unit/adapters/aws/` | create | Unknown-field detection on a tiny plan dict (an unknown subnet ID is ignored, an unknown policy is not); source index lines on `demo-infra/` files; ECS `RUNS_AS` resolves `family:revision`; coverage counts a made-up skipped type; build counts on `fixtures/intern` base and head |

## Steps

1. Write tests from the intern fixture first: node counts per kind (4 users, 3 groups, 11 roles, 6 workloads, 19 resources, 17 requirements), the new `MEMBER_OF` edge in head, its evidence file and line.
2. Implement `plan.py`, then `source_index.py`, then `build.py`.
3. Run against every fixture; nothing may raise.

## Done when

- [ ] Intern base has 4 users, 3 groups, 11 roles, 6 workloads, 19 resources and 17 requirements; head adds exactly one `MEMBER_OF` edge
- [ ] Every edge has evidence with a file and line, or `unknown` with a reason
- [ ] Both ECS workloads run as their task roles, never as `ecs-task-execution`
- [ ] An unknown policy becomes an unknown edge and an entry in `unknowns`; every skipped type is counted
- [ ] `pytest -q` and `ruff check .` pass, and `AI_USE.md` has this task's line

## Out of scope

- IAM evaluation and `CAN` or `CAN_ASSUME` edges (E2)
- Workflows (FM1)
- Code (C2)
- FalkorDB (E3)
